# دستور المشروع — حقيبة الأستاذ

> يجب على antigravity قراءة هذا الملف قبل أي عملية توليد كود، وإعادة قراءته عند الشك.

## 1. الرؤية

منصة SaaS جزائرية (عربي/فرنسي) للأساتذة، تقدَّم عبر اشتراك مدفوع (شهري / 6 أشهر / سنوي)، وتولّد بالذكاء الاصطناعي دروسًا كاملة، تمارين، وامتحانات مع سلالم تنقيط وحلول.

## 2. المبادئ غير القابلة للتفاوض

1. **عزل الوحدات (Module Isolation)**: كل ميزة = مجلد مستقل تحت `/modules/<اسم-الميزة>`. يُمنع أي استيراد مباشر لملف من module آخر. كل تواصل بين الميزات يمر إلزاميًا عبر `/core`. كل module يجب أن يعمل أو يُعطَّل (kill switch) بشكل مستقل دون كسر بقية المنصة — تمامًا كإضافات WordPress أو Laravel Modules — وأي فشل داخل module واحد لا يجب أن يوقف module آخر أو الـ core.
2. **Mobile First**: كل واجهة تُصمَّم وتُبنى ابتداءً من عرض ~360px، ثم تُحسَّن تدريجيًا للشاشات الأكبر. لا يُقبل تصميم يُبنى للديسكتوب أولاً ثم "يُصغَّر".
3. **الأمان أولاً**: أي كود يتعامل مع مصادقة، صلاحيات، دفع، أو بيانات شخصية يجب أن يطبّق كل بند في `06-security.md` دون استثناء، ويُراجَع قبل الدمج النهائي.
4. **تكلفة صفر على البنية التحتية**: تُستخدم فقط خدمات Cloudflare المجانية (Pages, Workers, D1, KV, R2, Access, Turnstile...). المصروف الحقيقي الوحيد المقبول هو استدعاءات الذكاء الاصطناعي (ومزوّد بريد صادر خارجي بخطة مجانية عند الحجم الصغير). لا تُستخدم Durable Objects أو Queues أو Images أو Stream إلا بقرار صريح من مالك المشروع بعد تجاوز الحصص المجانية.
5. **ثنائية اللغة من الأساس**: كل نص وكل تخطيط (layout) يجب أن يدعم العربية (RTL) والفرنسية (LTR) منذ أول سطر كود، عبر خصائص CSS منطقية (`inset-inline-start`, `margin-inline-start`, `ps-`/`pe-`...) لا خصائص فيزيائية ثابتة (`left`/`right`, `pl-`/`pr-`).
6. **التحقق من الصلاحية دومًا في الخادم**: عرض/إخفاء عنصر في الواجهة ليس حماية. كل مسار API لأي module يجب أن يتحقق من صلاحية المستخدم (RBAC للمدير، Plugin entitlement للأستاذ) في الخادم قبل التنفيذ، بدون استثناء.
7. **لا حذف بيانات نهائيًا دون تأكيد صريح**: كل حذف (مستخدم، باقة، محتوى) يجب أن يكون Soft Delete (أرشفة) بشكل افتراضي، ما لم يُطلب حذف نهائي صريحًا.

## 3. التقنيات المعتمدة (Tech Stack Lock)

- **الواجهة والخادم**: Next.js (Fullstack) — يُولَّد الكود عبر antigravity.
- **الاستضافة/التشغيل**: Cloudflare Pages (تطبيق الأستاذ) + مشروع Pages ثانٍ منفصل (لوحة المدير، على نطاق فرعي مستقل).
- **قاعدة البيانات**: Cloudflare D1 (SQLite).
- **التخزين المؤقت/الجلسات**: Cloudflare KV.
- **الملفات (PDF/Word المولّدة، الشعارات)**: Cloudflare R2.
- **حماية لوحة المدير**: Cloudflare Access (Zero Trust).
- **الحماية من الروبوتات**: Cloudflare Turnstile.
- **البريد الصادر (أكواد التفعيل، الإشعارات)**: مزوّد خارجي (Resend أو Brevo أو Postmark) — Cloudflare Email Routing للبريد **الوارد فقط**.
- **الطابور**: جدول `jobs` في D1 + Cron Trigger يفحص الأعمال المعلّقة (لا Durable Objects، لا Cloudflare Queues، ما لم يُقرَّر غير ذلك صريحًا).

## 4. قاعدة إلزامية لـ antigravity عند التنفيذ

- لا تُعدّل أكثر من module واحد في نفس المهمة، إلا إذا كان التعديل داخل `/core` نفسه ومصرَّحًا به صريحًا في المهمة الحالية من `04-tasks-phases.md`.
- عند الشك في نطاق التعديل أو في متطلب أمني، **اسأل قبل التنفيذ** ولا تفترض.
- بعد كل مهمة، **حدّث `PROGRESS.md`** حسب القالب في `10-progress-log-template.md` قبل الانتقال للمهمة التالية.
- لا تُدرج أي سرّ (مفتاح API، توكن) مباشرة في الكود المصدري؛ استخدم فقط متغيرات البيئة المعرَّفة في `.env.example`.
