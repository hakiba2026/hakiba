# قائمة الإعدادات المسبقة المطلوبة منك قبل بدء البرمجة

## 1. Cloudflare
- [ ] إنشاء حساب Cloudflare (إن لم يكن موجودًا).
- [ ] تفعيل Cloudflare Pages و Workers على الحساب (كلاهما ضمن الخطة المجانية).
- [ ] تثبيت Wrangler CLI محليًا (`npm i -g wrangler`) وتسجيل الدخول (`wrangler login`).
- [ ] إنشاء قاعدة بيانات D1 (`wrangler d1 create haqiba-db`) وحفظ `database_id` الناتج.
- [ ] إنشاء KV Namespace (`wrangler kv:namespace create haqiba-kv`) وحفظ الـ id.
- [ ] إنشاء R2 Bucket (`wrangler r2 bucket create haqiba-files`).
- [ ] تفعيل Cloudflare Zero Trust (Access) على الحساب — مجاني حتى 50 مستخدمًا — وتجهيزه لحماية نطاق `admin.<domain>` لاحقًا.
- [ ] إنشاء مفاتيح Turnstile (Site Key + Secret Key) من لوحة Cloudflare.
- [ ] إنشاء مشروعي Cloudflare Pages منفصلين: واحد لتطبيق الأستاذ وواحد للوحة المدير.

## 2. الدومين (Domain)
- [ ] شراء اسم الدومين النهائي للمنصة.
- [ ] إضافته إلى Cloudflare وتوجيه الـ Nameservers إليه.
- [ ] تحديد أسماء النطاقات الفرعية المستقبلية: مثل `app.<domain>` (تطبيق الأستاذ) و `admin.<domain>` (لوحة المدير).

## 3. مزوّد الذكاء الاصطناعي
- [ ] اختيار مزوّد AI للتوليد (مثل OpenAI أو Anthropic أو Google Gemini أو Cloudflare Workers AI) — القرار يؤثر على التكلفة والجودة، يُفضَّل تجربة مزوّدين قبل الحسم.
- [ ] إنشاء حساب + مفتاح API + ضبط سقف إنفاق شهري تحذيري (Budget Alert) لتجنّب فواتير غير متوقعة.

## 4. البريد الصادر (Transactional Email)
- [ ] إنشاء حساب في مزوّد بريد صادر خارجي (Resend أو Brevo أو Postmark) — Cloudflare Email Routing لا يصلح لهذا (وارد فقط).
- [ ] توثيق دومين الإرسال (SPF/DKIM) عبر إضافة سجلات DNS في Cloudflare حسب تعليمات المزوّد.
- [ ] الحصول على مفتاح API لهذا المزوّد.

## 5. الدفع (Payments)
- [ ] تحديد طريقة استقبال الدفع في البداية: تحويل بنكي/CIB/Edahabia بتأكيد يدوي من المدير (الأسهل في البداية)، أو بوابة دفع مبرمجة إن توفّرت لاحقًا.
- [ ] تحديد آلية تأكيد الدفع اليدوي (من سيراجع ويؤكد الدفعات في المرحلة الأولى).

## 6. المستودع البرمجي (Repository)
- [ ] إنشاء مستودع خاص (Private) على GitHub.
- [ ] التأكد أن `.gitignore` يستثني `.env` وأي ملف أسرار.
- [ ] ربط المستودع بمشروعي Cloudflare Pages (web و admin) لتفعيل النشر التلقائي، مع ضبط "Root directory" الصحيح لكل مشروع (`apps/web` و `apps/admin`).
- [ ] إعداد توكن Cloudflare API بصلاحيات محدودة (Pages + D1 فقط) وحفظه في GitHub Actions Secrets، لتفعيل تطبيق ترحيلات D1 تلقائيًا بعد كل نشر ناجح.
- [ ] وضع قالب لوحة التحكم المرفق (المستخرج من next-shadcn-dashboard-main.zip) في `/reference/shadcn-dashboard-template` داخل المستودع.

## 7. البيئة المحلية
- [ ] تثبيت Node.js (نسخة حديثة LTS) و pnpm (القالب المرفق يستعمل pnpm) أو npm.
- [ ] تثبيت antigravity وربطه بالمستودع المحلي.
- [ ] وضع كل ملفات حزمة `spec-kit` (هذه الحزمة) في جذر المستودع أو في `/spec/`.

## 8. المحتوى الأكاديمي الأولي
- [ ] تحديد أول مرحلة/شعبة/مادة تجريبية لإدخالها كبيانات seed (لتجربة معالج توليد الدرس أول مرة) — لا حاجة لإدخال المنهاج الكامل من اليوم الأول.

## 9. القرار اللغوي
- [ ] تحديد اللغة الافتراضية عند أول زيارة (عربي أم فرنسي) — يمكن تركها قابلة للتغيير من المستخدم لاحقًا بأي حال.

## 10. المشروع القديم (اختياري، عند الجهوزية)
- [ ] إن كان مشروع Laravel Filament + MySQL القديم جاهزًا، ضع كامل الكود (بما فيه `database/migrations`, `database/seeders`, الموديلات، وملف `.env.example` القديم للاطّلاع على أسماء الحقول) في `/reference/legacy-laravel-filament`.
- [ ] لا تضع بيانات مستخدمين حقيقية أو أسرار فعلية (مفاتيح API، كلمات سر حقيقية) في هذا المجلد؛ استعمل نسخة نظيفة من الكود فقط.
